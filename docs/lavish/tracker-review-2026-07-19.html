Commander Tracker — Full Review

2026-07-19 · three parallel reviews (correctness · product/UX · code health & PWA) over the whole repo at v18

Conclusion The stats core and the hard-won SW update pipeline are genuinely solid — but sync has four real data-correctness bugs worth fixing before any new feature, and the two highest-value product wins are embarrassingly cheap because the code already exists.
  1. Fix sync first — per-record merge reverts edits, deleted decks resurrect, duplicate deck ids, and import/pull can persist (and push!) corrupt state.
  2. Free stats are lying dormant — wilson() is written & tested but unused: the deck leaderboard ranks a 1-game 10.0 above a 12-game 7.1.
  3. Rivals is starved by logging friction — nearly all opponent placements are null in practice; tap-to-eliminate in the live game would fix the data at the source.
  4. Don't split app.js — extract only the pure logic (merge, ties) for tests; the rest is fine at 1400 lines.

Feature menu (ranked by value-for-effort for a 2-3-games/month fixed group)

1 · Per-player deck prefill in Log S quick win

Pick "Miel" → commander prefilled with their most-recent deck (same lookup topCommander() already does). Turns quick-log into ~6 taps for the common case.

2 · Real backup: file download + import preview S quick win

Blob download (mtg-tracker-2026-07-19.json) + file picker + confirm diff ("import has 42 games, you have 45 — continue?") instead of the copy-paste textarea. Pairs with the import validation P0. Zero-code bonus: link to the gist's revision history for disaster recovery.

3 · Honest leaderboard via the dead wilson() S quick win

Rank decks by rating shrunk toward 5.0 by sample size (display the raw number). Stops a 1-game 10.0 outranking a 12-game 7.1. One sort change; the stats function is already written and tested.

4 · Game duration for free S

The live game already knows when the pod sat down — stamp startedAt, compute duration at save. Avg length per pod size / per deck, zero extra taps.

5 · Tap-to-eliminate in live game M

"☠" per row during the game assigns places as people die (ties = two taps together; drag stays as fallback). Makes opponent placements the default — which is what actually unlocks Rivals/nemesis, currently starved (seed data: every opponent placement null). Byproduct: elimination timeline.

6 · "How the game ended" chips S/M

One optional tap at finish: Combat / Combo / Attrition / Stax / Scooped. Answers the most common post-game question ("what actually kills this pod?").

7 · History filters + read-only game view S

Chip row (my deck / opponent / pod size) over History. Also: tapping a row currently lands on the destructive edit screen — add a view step.

8 · Per-my-deck matchups in deck detail S/M

Parametrize bogeyDecks() by my deck: "Belbe struggles vs Reyhan (0/3)". The question a deckbuilder actually asks; needs the shrinkage treatment at n=2-4.

9 · Deck bracket / power level M

Bracket 1-5 per deck → "6.8 overall, 4.9 in higher-bracket pods". Settles the "your deck is just stronger" argument with data.

10 · Multi-perspective "view as" M/L

Per-device viewAs setting over the shared gist → each friend gets their own Overview/Rivals. The rendering already generalizes (overviewBlock(games, pid)); the "me" hardcoding + the P1 null-seat crash are the blockers. Converts a personal tool into the group's tracker.
